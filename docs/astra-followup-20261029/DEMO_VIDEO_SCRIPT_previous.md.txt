### 🎬 Scene 3: Audit and Simulated Repair (0:40 – 1:20)
- **On Screen**:
  1. Click **"Analyze code"** on `payment_webhook.ts`. The **Findings** panel surfaces the configured rule violations:
     - 🔴 `SEC-001` (Line 4): Plaintext credential detected (`STRIPE_SECRET`).
     - 🟡 `SYN-001` (Line 8): Missing leading `$` in `$json` expression (`json.customer.email`).
     - 🟠 `GOV-001` (Line 11): Unguarded direct communication dispatch without HITL gatekeeper (`dispatchSlackAlert`).
     - Initial compliance score: **45 / 100 [FAIL]**.
  2. Click **"Repair source"**. The self-healing loop triggers.
  3. The **Repair** tab displays the execution trace:
     - Step 1: Invariant detection.
     - Step 2: Simulated repair trace, labelled `MOCK_SIMULATED`.
     - Step 3: Proposed patch and static verification results.
- **Presenter Voiceover (EN)**:
  > *"Clicking 'Analyze code' detects three configured rule violations, scoring this sample at 45 out of 100. We click 'Repair source'. This run uses deterministic simulation, labelled MOCK_SIMULATED. Its trace illustrates the proposed repair: moving the credential to an environment variable, adding a human approval gate before the Slack dispatch, and correcting the dollar-json expression."*

### 🎬 Scene 4: Changes and Evidence (1:20 – 2:00)
- **On Screen**:
  1. Click on the **Changes** tab: side-by-side full-width source diff showing line-by-line additions and removals.
  2. Expand **Run details & evidence** below the results: shows final rule score (**100 / 100**), request timing, provenance (`MOCK_SIMULATED`), and click **"Download run evidence"**.
  3. Brief terminal view: execute `node --import tsx --test src/tests/patch-structure.test.ts` to visually demonstrate the AST structural guard immediately rejecting blank proposals and exported function removals while preserving original source.
- **Presenter Voiceover (EN)**:
  > *"The orchestrator rechecks the configured rules and TypeScript diagnostics, and rejects patches that lower the rule score. An AST structural guard checks candidates before acceptance: blank code or patches that remove exported functions are rejected, preserving the original source code. Incomplete repairs yield PARTIAL with review required, preventing unearned SUCCESS claims. Runtime behavior and business contracts remain NOT_VERIFIED: proposed code is not executed in the application. Changes shows the full source comparison. Expand Run details and evidence to see the request duration, actual rule score and simulated provenance. 'Download run evidence' exports the session as JSON for review."*

## 🎙️ Recording Best Practices
- **Resolution**: 1920 × 1080 (1080p) at 60 FPS.
- **Audio**: Clean microphone without room echo.
- **Timing**: Maintain a brisk, confident delivery to keep total runtime around 2:40.
